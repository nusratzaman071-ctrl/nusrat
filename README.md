## 1. What is Version Control?

**Version Control** is a system that records changes made to files over time. It helps us keep track of different versions of a project, compare changes, and return to an earlier version when necessary.

## 2. What is Git?

**Git** is a distributed version control system used to track changes in files and manage different versions of a project. It allows users to save changes as commits and work on projects efficiently.

## 3. What is GitHub?

**GitHub** is an online platform that hosts Git repositories. It allows users to store projects, manage files, track changes, collaborate with others, and publish websites using GitHub Pages.

## 4. What is Git Bash?

**Git Bash** is a command-line application that allows users to use Git commands through a terminal. For example, users can use commands such as `git status`, `git add`, `git commit`, and `git push`.

## 5. What are the Parts of GitHub?

- **Repository** – A place where a project and its files are stored.
- **README.md** – A file that provides information about the project.
- **Commit** – A saved record of changes.
- **Branch** – A separate line of development.
- **Pull Request** – A way to propose and review changes.
- **Issues** – Used to report problems and track tasks.
- **GitHub Pages** – Used to publish websites from a repository.

## 6. What are the Stages of Git/GitHub?

1. **Working Directory** – We create or modify files here.
2. **Staging Area** – We select changes that should be included in the next commit.
3. **Local Repository** – The selected changes are saved as a commit.
4. **Remote Repository** – The local commits are uploaded to GitHub.
5. **GitHub Repository** – The project is stored online and can be shared or collaborated on.
